Files, keys, updates

On disk

~/.scope/                 # SCOPE_HOME; override it with launchctl setenv SCOPE_HOME …
├── config.json           # declared scopes + preferences
├── drivers/*.json        # driver profiles
├── threads/<id>.json     # one record per thread
├── tasks/<id>.json       # one record per task
├── graph/<scope>.json    # the repository cards
├── sandboxes/            # the task worktrees
├── ui-state.json         # selection, expansion, panel widths
├── scope-visits.json     # when each scope was last looked at
├── assist.json           # the assistant's calls today, per tier
└── scope.sock            # hook events

Every store writes atomically. A file with a newer schema version than the running build is reported and left alone, never overwritten; a corrupt file is quarantined next to it rather than deleted.

The disk is the state. config.json, tasks/*.json and threads/*.json are watched: edit one in an editor — rename a topic, fix a field, remove a record — and the sidebar, the inspector, the CLI and the MCP tools follow without a restart. Scope tells its own writes from yours by the bytes (it keeps a fingerprint of what it last wrote or read), never writes anything back on a reload, and leaves a file that does not parse alone until it does, keeping what it had. A thread that is running keeps what its process knows (state, exits, session id) and takes the rest from the file.

The command palette

⌘K opens one field over everything: the actions of the current context, the files of the selection, the repositories of the scope and the open threads. ⌘P opens it straight in file mode.

Ask Orchestrator… (⇧⌘K) turns the palette into a message field addressed to the scope's orchestrator: ↩ sends, ⇧↩ starts a new line. Send to Thread… does the same for any thread, picked from the Go to Thread list. The message is typed into the thread as if you had typed it there; a stopped thread is started for it. Nothing moves on screen: a toast says where the message went, and Show goes there. A search that matches nothing, or reads as a sentence, offers Ask Orchestrator: … as its last row, so ⌘K, type, ↩ is enough.

To answer a waiting thread without switching to it, right-click its row in the sidebar and pick Reply… (or press ⌥↩ while the sidebar list has the keyboard). A field opens under the row with the end of the agent's last answer above it; ↩ sends, Esc closes.

While a terminal has keyboard focus it keeps ⌘K for itself. Click outside the terminal, or use Go → Command Palette…, until that is fixed.

Settings

  • General — config folder, default driver, editor command, terminal font size, appearance (follow the system, or always dark, which is what agent TUIs assume) and cursor shape — underline, bar or block, steady or blinking; a blinking caret fades in and out rather than switching on and off, and a program can still ask for its own shape — whether ⌥ types the character your layout puts there (the default, so a French keyboard still gets its braces) or acts as Meta, plus notification status and whether notifications quote the agent, and under Anywhere the two system-wide shortcuts (click the field, press the keys; ⌫ removes one) and which tab the quick panel opens on.
  • Shell Environment — how the login shell is probed, and the resulting PATH.
  • Drivers — every profile, the binary it resolves to, and Reload.
  • Automation — install the scope command line on your PATH, whether agents may drive Scope, how deep agents may open agents, and whether opening a thread or creating a task asks you first; the scheduled prompts of each scope, and whether a missed one fires at launch. See Command line and MCP.
  • Assist — off, the on-device model only, or that model with Haiku as a capped second opinion; what the assistant may decide, and what it did today. See the assistant.

The editor command is a template: ["code", "-g", "{file}:{line}"]. {path}, {file} and {line} are filled in; unused parts are dropped rather than left dangling.

Updates

Scope ships with Sparkle and keeps itself current on its own: it checks the signed appcast attached to the latest GitHub release every hour, and again when you come back to the app or wake the Mac, then downloads and verifies the release (EdDSA signature) in the background. A ready release is installed when you quit Scope. To have it sooner, a band across the top of the window and Scope → Restart to Update relaunch the app — never on their own, since a relaunch hangs up every running thread. Scope → Check for Updates… still checks on demand. Prereleases (v1.0.0-rc.1) are excluded from the stable feed.

What Scope touches

  • It reads your declared folders — files, git metadata, README and manifests.
  • It writes only under ~/.scope/ and its own Application Support folder — with two exceptions you ask for: git operations you trigger from a panel, and the worktrees it creates for tasks.
  • It sends nothing anywhere. Network traffic comes from the agents you launch, from git, gh, and from the update check.

Building and releasing

make generate            # Scope.xcodeproj from project.yml
make build               # Debug .app (CONFIG=Release for release)
make run                 # build + open
make test-one FILE=SlugTests
swift build              # the ScopeKit package alone

Releases are driven by tags: pushing vX.Y.Z builds a universal DMG, attaches it to a GitHub release with its checksum and the Sparkle appcast, and publishes it. The version is the tag; nothing in the tree is bumped. See the README for the full pipeline and its optional signing secrets.
